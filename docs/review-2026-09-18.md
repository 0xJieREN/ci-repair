# Repository review — 2026-09-18

Scope: current source, tests, dependency lock, Docker environment and CI flow.
The review covers project requirements and correctness; no broad framework
migration or deletion of historical run artifacts was needed.

## Model layer

The project already reused `DefaultAgent` and `LitellmModel`; it did not implement
an LLM service or reasoning loop. The CLI now calls mini-SWE-agent's native
`get_model()` factory. Supported CLI adapters are `litellm` (default) and
`openrouter`, both with tool-call prompts. Other upstream adapters are not
advertised until their response/prompt/budget contracts are checked here.

The official factory handles adapter initialization and Anthropic cache-control
defaults. Provider calls, tool parsing, cost tracking and trajectory format stay
upstream. Credentials stay in environment variables. Pricing registry paths are
read after the explicit dotenv load, avoiding import-time environment capture.
No custom model abstraction was added. Test-only ScriptedModel was replaced by
the upstream `DeterministicModel` via the same factory.

Source inspected: installed and pinned mini-SWE-agent 2.4.6,
[model factory](https://github.com/SWE-agent/mini-swe-agent/blob/v2.4.6/src/minisweagent/models/__init__.py).

## Correctness fixes

1. **Container command timeout:** upstream Docker execution bounds the client
   process but can leave the shell running inside the container. A small
   environment override adds GNU timeout around the inner command, with kill
   grace and an outer timeout. A Docker regression checks that a delayed write
   does not happen after timeout. Timeout/killed exit codes cannot qualify as
   successful baseline reproduction.
2. **False PASS edge case:** a zero exit code accompanied by a verifier exception
   could pass when it was the second check. Both checks now require zero exit and
   no exception metadata. Covered with a controlled transport-failure regression.
3. **Snapshot mismatch:** Git archive attributes can omit or substitute committed
   files. The generated archive is now checked against Git blob IDs, file types,
   executable modes and the complete path set. Changed exports fail closed;
   export-ignore/export-subst are not silently accepted as the original commit.
4. **Budget validation:** NaN/infinite budgets are rejected instead of disabling
   effective cost limits. Upstream between-call cost checks can still overshoot
   by one response; this is an estimate, not a hard provider spending ceiling.

## Efficiency and maintenance changes

- One metadata API request per collection instead of querying latest and then
  the same attempt again; explicit historical attempts do not load latest state.
- Shared checkout helper fetches only when the target commit is absent locally.
- CI context/log mismatches are rejected before Docker inspection.
- Long tool observations retain both head and tail within a bounded excerpt,
  preserving final tracebacks without feeding entire outputs into the model.
- One acceptance script replaces duplicated CI/local test instructions and owns
  local Colima cleanup. It reuses uv and Docker caches without extra services.

Baseline, repair and verification remain isolated. The follow-up verifier change
uses separate containers for each of the two checks as well; reusing a mutable
container would weaken independent verification.
No parallel agents, vector store, container pool, or new backend service was added.
For future larger workloads, measure per-phase timings and repair success on a
representative corpus before introducing concurrency or automatic test selection.

## Remaining boundaries

This is an alpha and a controlled test suite, not an exhaustive security audit.
The sandbox is not a hostile multi-tenant service. Host-side output capture is
still buffered; bounding model context is not a hard bound on RAM used by a
pathologically verbose process. Reports/digests assume trusted local evidence,
not signed third-party attestations. Network-dependent tests, fork publication,
automatic merge-to-head reverification, live PR HTTP acceptance, and fully
replicating a GitHub-hosted environment remain outside the current gate.

Existing `runs/` evidence and `.env` were retained and stay Git-ignored. The uv
environment is dependency-managed, not redundant project code, and was retained.
See [local/server verification](verification.md) for the recommended execution path.
